# Towards High-Performance eBPF-based OS Scheduling for Serverless Functions

[![License](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](https://opensource.org/licenses/Apache-2.0)

This project investigates the impact of different OS scheduling policies on the performance and user costs of serverless functions. The goal is to improve the performance and reduce the cost of Function-as-a-Service (FaaS) systems by exploring alternatives to the default Linux scheduler (EEVDF).

## Requirements

- Python 3.10+
- LaTeX (for plotting)

```bash
pip install -r requirements.txt
```

### Dataset
1. Download `AzureFunctionsInvocationTraceForTwoWeeksJan2021.rar` from the [Azure Public Dataset](https://github.com/Azure/AzurePublicDataset).
2. Place the `.rar` file into the `load-instance/data/` directory.

### Local
- Linux Kernel >= 6.12 (Verify using `uname -r`)
- Requirements of [sched-ext](https://github.com/sched-ext/scx)
- Requirements of [OpenLambda](https://github.com/open-lambda/open-lambda)

### Cloud (GCP)
- Terraform
- Google Cloud SDK

1.  **Activate Billing:** Enable billing in the Google Cloud console.
2.  **Create Project:** Create a new Google Cloud project.
3.  **Configure Terraform:**
    -   Store your Google Cloud project ID in `terraform/terraform.tfvars` under the `gcp_project_id` variable.
    -   Set your desired deployment location using `gcp_region` and `gcp_zone` in the same file.
4.  **Enable APIs:**
    -   Activate the Google Compute Engine API.
    -   Activate the Bare Metal Solution API.
5.  **SSH Keys:**
    -   Create a public/private key pair using `ssh-keygen`.
    -   Set the `gcp_private_key_filepath` and `gcp_public_key_filepath` environment variables in `terraform/terraform.tfvars` to the paths of your keys.

## Results and Evaluation

The results of each measurement run are stored in the `./results/[date]` directory, where `[date]` is the timestamp of when the measurement was started. Each measurement generates the following data:

-   **Plans:** The generated workload plans are stored in the `plans` directory.
-   **Execution Durations:** The execution durations for each scheduler run are stored in a separate file in the `results` directory, prefixed with the index of the associated plan.
-   **Scheduler Order:** The executed scheduling commands and their execution order are stored in `logs/sched-order.txt`.
-   **Logs:** Logs from OpenLambda and the `sched_ext` schedulers are stored in the `logs` directory.

### Generate Plots

```bash
python evaluation/generate_paper_plots.py ./results/[date]
```
The generated plots will be saved in the `./results/[date]/figures` directory.

## Parameter Search

This project evaluates a wide range of schedulers and their parameters. The configurations are generated by `scripts/generate_scheds.py` and stored in `scripts/scheds.sh`.
